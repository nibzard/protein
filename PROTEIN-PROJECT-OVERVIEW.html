What we learned

These are the conclusions that survived the whole project, not just one successful run. Each is tied to a measured result, a failed assumption, or an explicit architecture decision.

Protein is not an LLM inside a cell. It is a durable identity that can sleep, wake, decide, request the right compute, and preserve the evidence needed to continue safely.
Synthesis

The project began with a cellular-automaton metaphor. The useful part was locality and emergence. The unhelpful part was pretending that movement or survival rules were meaningful agent work.

Decision

EVIDENCE ≠ GENERALIZATION

From Conway to useful work

The project did not begin with the final architecture. It began with a cellular metaphor, hit two unhelpful extremes, and then found a sharper question: what happens when many durable agents do real, bounded, verifiable work near one another?

00

Keep locality. Throw away pretend movement.

ORIGINAL CONVERSATION · 08 AUG 2026

The first idea borrowed the shape of Conway’s Game of Life: many cells, simple local visibility, and system-level patterns emerging from local behavior. An early proposal used LLM choices as cellular movement or survival. That was rejected as a misuse of intelligence. A later correction drifted too far toward generic business workflow. That was rejected too.

The useful middle was concrete: each cell holds a persistent problem-solving identity and a candidate artifact; agents explore, test, challenge, combine, review, or adopt real work using bounded model and tool calls. The grid constrains information. It is not a cartoon world.

  • “Death” belongs to a bad candidate, not to the durable agent identity.
  • Fitness must come from tests or independent evaluation, not an agent’s self-report.
  • The visualization should show work, lineage, evidence, cost, and recovery. Random motion tells us nothing.
Project direction
Real artifacts became the unit of progress. Code, tests, counterexamples, patches, proof certificates, and receipts replaced simulated movement.
01

A broad use-case list did not prove a product.

PRODUCT RESET · 09 AUG 2026

A hundred possible use cases showed that many jobs can be represented as sleeping state machines. It did not show why anyone would deploy celld or Protein. The initial “one goal, one bounded step, mostly waiting” case-shepherd abstraction had overfit one harness into the core.

The demand filter became stricter: would the embedding product need a fleet of independently addressed, long-lived identities with private state, schedules, live sessions, and recovery? If not, cron plus a database, an ordinary process, a workflow engine, or another actor platform is probably the better answer.

  • Cron plus a shared database wins for a small fixed set of jobs.
  • A normal process wins continuous library-heavy or artifact-heavy work.
  • Temporal is stronger for finite workflows with mature signals, retries, and compensation.
  • Restate and Rivet already cover much of the keyed durable-actor territory.
Negative finding
Representable is not deployable. The product wedge narrowed to embedded fleets of independently addressed agent identities.

Read the product thesis

02

Reset the primitive around identity.

AGENT CELL THESIS · 09 AUG 2026

The native unit became one named Agent Cell: a durable control-plane actor that receives events, reconciles compact private state, commits action intent, records outcomes, and may become non-resident when celld evicts an eligible idle isolate. One agent can contain many sequential or overlapping runs; a run is not the identity.

This also set the future-framework rule. Protein would be a proving ground, but reusable code would be extracted only when multiple working environments earned the same abstraction. Runtime semantics stay below the line; grids, generations, roles, scoring, and experiment choreography stay above it.

Core primitive
Agent ≠ run ≠ model. The durable name and private state survive temporary activation and replaceable intelligence providers.

Project vision · Decision log

Probe the substrate, then build the minimum

Before inventing an agent framework, we read celld’s boundary, ran Cloudflare Agents on it, forced the convenient implementation to fail, and then built only the durable semantics the experiments required.

03

Celld dictated a control-plane/data-plane split.

SUBSTRATE AUDIT · 09 AUG 2026

Celld gives every named cell a private SQLite database, one alarm, HTTP and RPC handling, hibernatable inbound WebSockets, and bucket-backed restoration. Handlers are single-threaded but can interleave while awaiting. It does not provide a functional persistent filesystem, subprocesses, general TCP, a queue service, a workflow service, browser automation, a blob binding, or native AI.

That absence was productive. The cell should own identity, policy, compact state, action intent, leases, receipts, and history. External capability providers should own model inference, checkouts, shell commands, browsers, evaluators, sandboxes, and large artifacts.

Substrate facts
Small durable brain, replaceable hands. The boundary later supported model, bounded-evaluator, and Linux capability tiers without changing the cell primitive.

Research notes

04

The compatibility probe worked until its assumptions mattered.

CLOUDFLARE AGENTS 0.20.1 + CELLD 0.1.0 · 09 AUG 2026

After an esbuild workaround for a bare path import, Cloudflare Agents state, direct SQL, schedules, hibernatable WebSockets, alarm-backed callbacks, and fresh-node restart recovery all ran on celld. That made the SDK valuable prior art, but not a drop-in base.

The first RepoAgent committed an action claim and then stayed stuck in delivering. The SDK’s queue() launched its flush without binding the awaited outbound work to the event lifetime; celld ended the handler and abandoned the pending request. Protein therefore took ownership of an alarm-backed durable inbox and outbox.

A more decisive failure followed. The prebundled SDK was about 1.7 MB. A 1,000-cell activation attempt reached roughly 9.9 GB RSS on an 11.7 GiB host and timed out under pressure. The fleet premise and the heavyweight base class were incompatible.

Falsified path
State: pass. Queue durability: fail. Fleet footprint: poor. Compatibility at the API surface did not imply suitable lifecycle or density behavior.

Compatibility matrix

05

Build ProteinAgent directly on DurableObject.

MINIMAL RUNTIME + REPOAGENT · 09 AUG 2026

The replacement runtime implemented only the parts that had to survive activation boundaries: canonical state, deduplicated events, runs, durable action intent, leases, terminal receipts, a bounded journal, one-alarm reconciliation, and hibernatable sockets. Applications return an AgentTransition describing state, run changes, and external action intent; the runtime commits that intent before dispatch.

The RepoAgent example made the separation concrete. Its cell remembers repository goals and run state. An external idempotent executor owns checkout, shell, tests, and patch artifacts. A restart while an action was in flight recovered by stable identity rather than repeating a second logical job.

The measured minimal baseline activated 1,000 of 1,000 named cells in 19.46 seconds with 3,459 MiB peak celld RSS. The bundle measured for that run was 34.2 KB; the later reconciliation build is 40.0 KB and has only been regression-tested at 100 cells.

Local baseline
~50× smaller bundle than the SDK prototype. Local MinIO, four CPU cores, one host. These are development measurements, not production capacity guarantees.

Runtime contract · Measurements

At this point Protein could survive restarts and coordinate external work. The next job was not adding features. It was trying to break the safety story.

THE PROJECT MOVED FROM “DOES IT RUN?” TO “WHAT CAN IT HONESTLY GUARANTEE?”

Falsify the safety boundary

Durable execution is defined by what happens at the worst moment. We killed the process at thirteen action checkpoints, then introduced a second owner, a partition, and adversarial clock skew.

06

Crash every side of dispatch.

13-CASE SIGKILL MATRIX · 09 AUG 2026

The proof harness added persistent dispatch markers, revision claims, deterministic checkpoints, an executor ledger, and authoritative reconciliation. It killed celld before claim, after claim, around dispatch, after receiver acceptance, and after local outcome commit.

Ten of thirteen cases passed. All tested idempotent cases converged to one logical remote job. The reconcilable case looked up prior acceptance and avoided redispatch. Three unsafe cases failed at action.dispatch_started and two later checkpoints because a fresh celld process could restore bucket state older than the local marker or receipt.

Even a locally committed outcome can be redelivered after restoration. A local “sent” bit is therefore not a stable external guarantee. Leases are recovery clocks, not locks, cancellation, or proof that an earlier request stopped.

10 pass / 3 fail
Idempotent and reconciled paths converged. Unsafe automatic effects did not. They remain descriptive records, not a supported delivery class.

Crash proof details

07

Split ownership, then watch both sides dispatch.

TWO-NODE PARTITION + 9 S CLOCK OFFSET / 12 S LEASE · 09 AUG 2026

The healthy-routing and immediate-partition phases behaved as expected. In the stale-owner window, node B’s clock was moved forward by nine seconds against a twelve-second lease while node A remained partitioned. Both believed they had authority and both reached executor dispatch for the same logical action.

The receiver saw two origins and two requests but collapsed them into one logical job because it honored stable idempotency. After healing, a fresh owner converged to the completed state. The test was deliberately adversarial; it does not claim ordinary NTP drift looks like this. It does prove that Protein’s local revision fence cannot repair two simultaneously authoritative celld owners.

A later architecture audit found another seam: current action IDs are only unique inside a cell, while the runtime passes the raw local ID as the idempotency key. Shared executors need a globally namespaced operation identity derived from deployment / cell class / cell identity / local action ID. Architecture v1 specifies it; runtime enforcement is still open.

Production blocker
No exactly-once claim. No high-stakes unsafe effects. Multi-host one-writer safety requires celld fencing and a rerun of this proof. Receiver semantics remain mandatory even then.

What the runtime can protect

  • Durable event deduplication and payload-conflict detection inside one cell history.
  • Committed action intent before external dispatch.
  • Lease-based recovery of abandoned actions.
  • Revision fencing against stale asynchronous commits in one owner history.
  • Reconciliation with an authoritative receiver.

What it cannot manufacture

  • Exactly-once external execution.
  • Idempotency at a non-idempotent receiver.
  • Cancellation of a live call merely because a lease expired.
  • Fencing between two active celld owners.
  • Durability stronger than the substrate’s acknowledged restore point.

Make model agents do real work

The runtime was ready before the research question was. We climbed an evidence ladder: authored interface, deterministic smoke, live Responses tool loops, exploratory comparison, then a frozen fixed-quality experiment. Each rung answered a different question.

08

First, distinguish the picture from the system.

AUTHORED BROWSER SCENARIO · 09 AUG 2026

The first cellular screen made the interaction model visible: a grid of candidates, score, lineage, activity, and per-cell history. It was useful for defining the product language, but it did not run Protein, celld, an LLM, a tool executor, or hidden evaluation.

That distinction matters because agent demos often turn presentation into evidence. Here, the UI was a contract preview only. It showed what future receipts and journals should project. Those records did not exist yet.

Presentation only
No runtime claim. The authored scenario was retained as design work, then superseded by real evidence bundles.
09

Use a deterministic 4×4 smoke to prove the path.

16 CELLS × 3 GENERATIONS · 09 AUG 2026

The next version ran real SwarmCell identities through celld. A deterministic policy generated actions, recorded candidate lineage, evaluated artifacts, restarted the runtime, and reconstructed the final board from durable state and action records.

This established that many cells could traverse the same event → action → receipt loop and that a dashboard could be projected from authoritative records. It still proved no autonomy or intelligence. The deterministic behavior was scaffolding for runtime, evidence, and visualization. It was not a benchmark.

External services and files retained raw provider replay state, artifacts, board state, and evaluator evidence. After the initial pilot used gpt-5.6-sol, the live research standardized on gpt-5.6-luna.

The exploratory comparison produced one local win, one isolated win, and one tie, with a median effect of −1.33 percentage points. The local condition used fewer recorded tokens, turns, tools, evaluations, and less elapsed time, but evaluation counts were unequal and evaluator noise was substantial.

12

The fixed-quality experiment found expensive context and compressed search.

10 PLANNED MATCHED PAIRS · 4×4 × 4 GENERATIONS · 09 AUG 2026

Ten alternating matched pairs compared local-neighbor exchange with isolated cells under the same Luna settings. Pair 3 contained an ambiguous provider attempt and a measurement-block failure. A later clean retry could not erase it under the frozen rules, so the authoritative confirmatory result is incomplete.

The nine valid pairs still provide descriptive evidence. Both arms reached the target in all nine. Isolated won seven non-tied pairs on Responses-token cost, local won none, and two fell within the ±5% tie band. Local median token cost at first verified reach was 26.50% higher. Local used fewer model requests, tools, public checks, discovery evaluations, and output tokens. Its input-token cost was 30.24% higher.

The mechanism spread candidates rather than combining work. Local runs created 147 unique candidates versus 270 isolated, finished with diversity 43 versus 142, and recorded 306 adoptions but only one directly neighbor-derived verified improvement. Across the accepted corpus, 320 cells completed 1,280 cell-generations with 20/20 restart recoveries. The runs emitted 7,714 known peer-owner-unreachable warnings, but no redeliveries, runtime or service errors, or HTTP 5xx responses.

Incomplete experiment
Communication cost is algorithmic. Compact artifact references and causal contribution measures became requirements for the next environment.

Full fixed-quality result

Turn exchange into repository work

The next environment replaced candidate propagation with code authorship, typed review, revision, public checks, hidden tests, and accepted artifacts. It produced a stronger demo and a more useful failure.

13

Four cells authored, reviewed, and revised code.

REPOSITORY-MAINTENANCE PILOT · 10 AUG 2026

Four Luna-backed Protein cells each repaired one JavaScript task: Unicode slug normalization, case-insensitive HTTP header merging, duration parsing, and capped exponential retry delay. Each cell reviewed its clockwise neighbor, revised its own artifact from a typed review, and submitted to a separate hidden evaluator.

Generated code ran inside networkless, read-only, capability-dropped Docker sandboxes. The pilot recorded 12 model jobs, 9,751 Responses tokens, four peer reviews, 4/4 public gates, 4/4 hidden gates, and 2.28-second celld restart recovery. All final revisions passed 28 combined public and hidden cases.

Vertical passed

THREE MATCHED PEER-VS-SELF PAIRS · 10 AUG 2026

Each arm used four durable cells, three Luna calls per cell, the same tasks, the same checks, and alternating condition order. Peer review won zero trials, lost one, and tied two. Peer finished at 82/84 aggregate cases versus self review at 84/84, despite nearly equal actual token use: 29,587 versus 29,973.

15

Extract monotonic acceptance.

FIRST EARNED GOVERNANCE PRIMITIVE · 10 AUG 2026

The regression exposed a rule that applied beyond repository maintenance. A child artifact may replace a verified parent only when it names that parent, preserves every gate the parent already passed, and passes all newly required gates. Otherwise the parent remains authoritative and the rejected child stays in the evidence trail.

This became the pure decideMonotonicAcceptance() primitive. A subsequent formal-protocol run integrated it and recorded four durable acceptance receipts while preserving all 13 proof obligations. The reusable seam was earned by two environments: revision governance for code and promotion governance for proof candidates.

Extracted primitive
Advice may branch history; evidence chooses the head. Failed children remain inspectable instead of overwriting the last known-good artifact.

Acceptance implementation

Put a solver above the models

A mathematical task made authority unambiguous. Luna cells could explore, repair, and critique a protocol, but Z3 alone decided whether the finite-state safety obligations held.

16

Twelve cells repaired a crash/retry protocol.

2×2×3 FORMAL POPULATION · 10 AUG 2026

The population used three responsibility layers: explorers, repair/invariant synthesizers, and adversarial proof checkers. It examined a finite protocol whose unsafe trace could retry an ambiguous effect without reconciliation. All four synthesis columns independently selected require_reconciliation.

Z3 proved initiation, transition preservation, four safety implications, and the policy forbidding unreconciled ambiguous retry. The final content-hashed SMT-LIB certificate replayed 13/13 obligations as UNSAT using Z3 4.15.3 and rejected three invalid mutations. The pilot used 12 Luna calls, 13,501 tokens, and recovered after restart in 2.85 seconds.

Model-generated proposals, solver-owned truth. The proof applies to the encoded finite-state model, not the entire TypeScript runtime.

RUNTIME CONFORMANCE · 10 AUG 2026

18

Refuse the 27-cell formal cube.

FROZEN SCALE PREFLIGHT · 10 AUG 2026

Before spending model calls, the project froze a nine-mutation suite, equal budgets, and explicit reasons that would justify scaling. Exhaustive Z3 enumeration solved 9/9 in 101.168 ms with no model. One centralized Luna cell solved 9/9 with 12 calls. A layered 12-cell Protein population also solved 9/9 with 12 calls.

No centralized miss, layered advantage, causally necessary neighbor artifact, cross-column conflict, or solver-cost pressure appeared. The gate therefore said do not run the larger cube on this task. Adding fifteen cells would measure orchestration volume, not collective intelligence.

Scale rejected
No 27-cell formal execution occurred. This stop decision became evidence that Protein’s experiment gates could constrain its own ambition.

Preflight result

Correct the cube thesis

The formal task rejected a bigger population as an intelligence experiment. It did not reject a cube as a systems experiment. The sharper vision was a durable agentic compute fabric: many lightweight identities, selective stronger compute, durable provenance, and recovery over time.

19

Ask a systems question, not only a benchmark question.

CORRECTED THESIS · 11 AUG 2026

The project’s long-term premise is not merely “many agents beat one.” Most future agents may need only a small durable cell for identity, local memory, work claims, schedules, relationships, and provenance. Some tasks need a bounded model call. Others need a narrow evaluator or a full Linux sandbox. The stronger resource should be requested when needed and its outcome returned as a durable receipt.

The resulting question became: can a large population of durable agents coordinate heterogeneous, escalating compute reliably and economically over time? A worthwhile cube would make wakes, handoffs, duplicate suppression, conflict, denial, recovery, provenance, and hibernation visible. Population size alone would prove nothing about intelligence.

Broader systems thesis
Durable cells → selective compute → durable evidence. The cube now had a reason to exist even without outperforming a centralized agent.

Corrected thesis note

COUNT CAUSAL WORK, NOT CHATTER

The architecture that emerged

Architecture v1 is an evidence-cutoff design, not an immutable endpoint. It separates the substrate, durable runtime, reusable policies, experiment code, external compute, and fleet-wide control so each layer can make only the claims it has earned.

Agent Cell

One independently named unit of durable memory and authority. It owns compact canonical state and may contain many runs.

Run

A bounded objective or attempt within an agent identity. Completing or failing a run does not destroy the agent.

Event

A deduplicated input with identity, payload hash, revision claim, and durable processing outcome.

Action intent

A committed request for an external effect. The runtime records idempotent, reconcilable, or unsafe; unsafe exists for ambiguity research but is unsupported for automatic production effects.

Receipt

Durable evidence that a capability accepted, completed, failed, denied, or left an operation ambiguous.

Artifact + relationship

Versioned work outside the cell plus a typed causal edge such as parent, review, conflict, duplicate, or acceptance.

01

Persist and deduplicate the event

Same identity plus same payload becomes one event. Same identity plus conflicting payload is rejected rather than silently merged.

02

Claim a state revision

The cell records which durable revision the transition is based on so stale awaited work cannot overwrite a newer local history.

03

Describe the application transition

Application policy proposes state changes, run changes, journal evidence, and bounded external action intent.

04

Commit state and intent together

The runtime persists the new compact truth and outbox record before any capability receives the request.

05

Reconcile or dispatch

An authoritative lookup comes first where available. The target contract carries stable global operation identity and a bounded lease; today the application must namespace the cell-local action ID.

06

Record outcome, then wake policy again

A terminal receipt becomes a new internal event. The agent decides what follows; an in-memory callback does not.

Built now. Still unproven.

The strongest way to explain Protein is to draw the claim boundary in public. The left side is implemented or reproduced in this repository. The right side remains an architecture target, an unresolved safety issue, or a future experiment.

Built or reproduced

The current evidence base

  • A minimal celld-native ProteinAgent with durable events, runs, action intent, receipts, journal, alarm reconciliation, and hibernatable sockets.
  • Idempotent and reconcilable external action paths with deterministic crash checkpoints.
  • RepoAgent, cellular optimization, repository-maintenance, formal-protocol, and compute-fabric environments.
  • Bounded OpenAI Responses tool loops using gpt-5.6-luna.
  • Public checks, hidden evaluators, Docker sandboxes, Z3 certificates, and artifact provenance.
  • Monotonic parent/child acceptance that retains last known-good evidence.
  • Restart reconciliation, equivalent-duplicate suppression, typed relationships, conflict resolution, and resident-pressure hibernation evidence.
  • Machine-readable run summaries, timelines, receipts, logs, and honest negative-result reports.
Not yet proven

The current production boundary

  • Celld-level owner fencing and safe multi-host failover under partitions and clock skew.
  • Exactly-once external effects or automatic high-stakes unsafe dispatch.
  • Runtime-enforced global operation namespacing across cells; Architecture v1 defines it, current code still passes a cell-local action ID.
  • Cell-authored compute escalation, capability discovery, decentralized routing, or continuous operation.
  • A real in-flight evaluator or executor-process crash with its own durable failed-attempt receipt.
  • Global queues, admission, quotas, fairness, capacity control, fleet registry, and cross-fleet observability.
  • Cancellation, human approvals, hostile multitenancy, secret brokering, schema migrations, retention, and journal compaction.
  • 10,000-cell sparse-fleet behavior, real object-store latency, steady-state cost, or a production SLA.
  • Learning, durable reputation, or an equal-budget population advantage over a strong sequential agent.

The present claim is substantial but narrow: Protein demonstrates many durable identities coordinating bounded, externally verified work through recoverable capability calls on one celld host.

IT DOES NOT YET CLAIM AUTONOMOUS FLEET CONTROL, MULTI-HOST SAFETY, OR SUPERIOR COLLECTIVE INTELLIGENCE.

The next architecture proof

The next run should not add another decorative topology. It should remove central orchestration in controlled increments and test whether a durable population can operate a real work stream under explicit capability, budget, and evidence constraints.

P1

Make cells author capability requests.

Cells should choose the cheapest adequate tier, state why escalation is necessary, name the evidence expected, and bind the request to a budget. Deterministic policy may approve, reduce, deny, or defer it.

P2

Add discovery and constrained executor pools.

Capabilities should advertise typed limits and current availability. Work should queue durably against bounded model, evaluator, and sandbox capacity so backpressure becomes visible rather than hidden in the runner.

P3

Enforce global operation identity and fleet policy.

Namespace every external operation by deployment, cell class, cell identity, and local action. Keep global admission, quotas, fairness, and one-logical-effect enforcement outside individual cells.

P4

Run real failure and longevity proofs.

Interrupt an in-flight evaluator, kill an executor process, retain a failed-attempt receipt, recover queued work, force migration between owners, and repeat the multi-host fencing harness after an upstream celld fix.

P5

Compare causal work under equal ceilings.

Run a strong sequential agent, isolated population, and interacting population against the same work stream, token ceiling, executor ceiling, and deadline. Attribute accepted outcomes to the interactions that actually changed them.
