The decision

Protein should not be “Claude Code running forever inside celld.” Celld has no shell, workspace, or durable JavaScript continuation. The native shape is a durable actor that controls work performed elsewhere.

Proposal

A named cell receives events, reconciles them against private state, commits action intent before external execution, records the outcome, and hibernates when no work is runnable.

Research method

The inquiry moved from broad possibility to falsifiable architecture. Documentation defined the expected substrate; executable probes tested compatibility; crash and fleet tests decided which implementation survived contact with celld.

01 · IDEATION

Generate widely, then distrust the list

One hundred use cases were researched and organized. This showed representational breadth, but not deployment demand. “Could run here” was separated from “would cause someone to deploy celld.”

02 · SUBSTRATE READING

Derive the primitive from celld

Named objects, private SQLite, alarms, hibernatable sockets, and bucket-backed placement point toward identity-centered actors. Missing shell, filesystem, workflow, and blob primitives force a control-plane/data-plane split.

03 · COMPATIBILITY PROBE

Run Cloudflare Agents instead of guessing

A pinned probe exercised state, schedules, WebSockets, restart recovery, and queued outbound work on celld 0.1.0.

04 · DISCONFIRMATION

Reject the convenient base class

The full SDK needed a packaging workaround, detached queue work was abandoned, and the 1,000-cell attempt reached approximately 9.9 GB RSS before timeouts. Extending the full Agent class no longer fit the fleet premise.

05 · MINIMAL IMPLEMENTATION

Build only the missing durable semantics

Protein was reduced to a direct DurableObject subclass with a transactional inbox, runs, action outbox, receipts, journal, one-alarm reconciler, and sockets.

06 · RECOVERY + FLEET

Test the boundary, not a toy counter

A RepoAgent dispatched to an external idempotent executor, survived interruption during an in-flight action, recovered on a fresh local celld cache, and completed a 1,000-cell activation run.

07 · SAFETY FALSIFICATION

Crash every boundary and split the owner

A 13-case SIGKILL matrix proved idempotent and reconcilable convergence but falsified unsafe marker and redelivery protection. A two-node partition/skew test then produced simultaneous A/B dispatch; the external idempotency ledger contained it to one logical job.

What celld changes

Celld already solves identity, ownership, local transactional state, activation, and restoration. An agent framework on top should exploit those choices rather than recreating a portable abstraction that hides them.

Native affordances

  • Name-addressed objectsA stable identity can be routed without querying a shared registry.
  • Private SQLiteState, event admission, action intent, and receipts can share one transaction boundary.
  • One intended active ownerPer-identity coordination is local in the normal case, but the new chaos harness falsified exclusivity in a stale-owner/skew window on celld 0.1.0.
  • HTTP, RPC, sockets, alarmsMultiple wake sources target the same durable identity, while idle instances leave memory.
  • Operator-owned bucketDeployments, cell databases, and ownership records live in S3-compatible storage.

Absent by design or today

  • No agent filesystemRepository checkout and artifacts require an executor or object store.
  • No subprocess sandboxGenerated code and shell tools do not belong inside the cell.
  • No durable promiseOpen fetches, timers, and closures cannot be treated as recovery state.
  • No global SQLFleet discovery, quotas, and cross-agent analytics need a control plane.
  • No current workflow serviceLarge, finite step graphs should integrate with one rather than inflate Protein.

The native primitive

An Agent Cell is an open-ended identity, not a goal and not a process. Runs, turns, and actions are records governed by that identity.

How it works

Protein adds the durable semantics celld does not supply as a single runtime contract. The important operation is not the model call; it is the transition around it.

1 · ADMIT

Canonicalize an event ID and payload. Equivalent repeats are accepted as duplicates; changed content conflicts.

2 · CLAIM

Increment attempts and revision. Record a lease in a short SQLite transaction.

3 · DECIDE

Run application or model logic outside the transaction against the claimed state.

4 · COMMIT INTENT

Fence on revision, then atomically persist state, run status, action intents, completion, and journal.

5 · EXECUTE + RETURN

Dispatch later with the action ID, persist the terminal receipt and outcome event together, then reconcile again.

One physical alarm, many logical deadlines

Pending events and actions contribute available_at. Claimed work contributes lease_until. Protein arms celld’s one alarm for the earliest timestamp, processes at most one runnable item, and re-arms if work remains.

Revision fences, not in-memory locks

Handlers may interleave while awaiting a model or tool. A decision commits only if the row still carries the claimed revision. Recovery reconstructs work from SQLite rather than resuming a promise.

The exactly-once boundary

SQLite and a remote API cannot share one atomic commit. Protein makes this explicit rather than hiding it behind a queue-shaped method.

SAFETY CLASSREQUIRED RECEIVER BEHAVIORUNCERTAIN DISPATCH

What passed end to end

Event deduplication, content-conflict rejection, external action dispatch, durable outcome handling, hibernatable WebSockets, restart from the bucket, interrupted-action redelivery, and 1,000 distinct cell activations.

What the failed prototype taught us

The Agents-based RepoAgent bundle was approximately 1.7 MB. Its 1,000-cell attempt was stopped after celld reached about 9.9 GB RSS and requests timed out under pressure. That observation rejected the dependency choice; it did not benchmark Cloudflare’s managed platform.

What would drive deployment?

The question is not whether a task can be modeled as an agent. Demand appears when high cardinality, sparse activity, private state, identity-local coordination, and self-hosting occur together.

STRONGEST ECONOMIC DRIVER

Embedded per-customer agent fleets

One durable agent per customer account, workspace, or owned resource. Private preferences, integrations, live sessions, and ongoing runs repeat at fleet scale. The embedding product supplies auth, provisioning, and fleet indexing.

REFERENCE HARNESS

Repository engineering agents

One cell remembers repository policy, approvals, runs, CI callbacks, and receipts. External executors own checkouts, commands, tests, and patches.

OPERATIONS

Service and incident agents

One identity reconciles alerts, deployments, diagnostics, operator chat, and remediation approval; it can stay live during an incident and hibernate afterward.

PHYSICAL FLEETS

Device and site agents

Sparse device, facility, vehicle, or site events map naturally to named local history and scheduled maintenance decisions. Not suitable for hard-real-time control.

PERSISTENT SOCIAL STATE

Rooms, communities, and characters

Stable identity, compact history, real-time reconnects, and cheap inactivity are native even when the model layer is replaceable or absent.

SOVEREIGN DEPLOYMENT

Organizational assistants

One agent per employee, team, or account on customer-controlled infrastructure. A large fleet can justify celld; one personal assistant usually cannot.

Boundaries that keep the idea honest

A minimal primitive stays useful by refusing adjacent platform responsibilities. Each rejected category already has a better substrate or requires capabilities celld does not provide.

Protein is not

  • A Codex clone inside celldNo shell, repository workspace, or process sandbox lives in the cell.
  • A model SDKModel choice, prompting, context assembly, and streaming policy belong to the application.
  • A workflow engineIt does not persist arbitrary continuations or orchestrate large step graphs.
  • A fleet control planeIt does not provision identities, maintain a global index, or enforce tenant-wide quotas.
  • An exactly-once effect systemRemote execution requires idempotency, reconciliation, or explicit ambiguity.

False demand signals

  • One page watcherCron and a row in Postgres are simpler.
  • One-shot research or codingNo long-lived keyed identity is needed.
  • Continuously hot agentsHibernation and sparse activation provide no advantage.
  • Global shared-memory swarmsPer-cell isolation fights the workload.
  • ETL or report pipelinesA workflow/data system provides better lineage and bulk coordination.

Roadmap by proof, not feature count

The next work should decide whether Protein deserves to remain a library. Adding more agent conveniences before closing the correctness and demand gaps would only increase sunk cost.

Continue when
  • Design partners need hundreds or thousands of customer-controlled agent identities.
  • The inbox/outbox and per-identity lifecycle remove meaningful application code.
  • External executors can honor durable action IDs and scoped capabilities.
  • Multi-node fault tests establish a safe ownership envelope.
  • Steady-state fleet cost remains favorable after hibernation and real object storage.
Shrink or stop when
  • Postgres plus ordinary services remain equally simple.
  • Restate, Temporal, Rivet, or managed Durable Objects match deployment needs better.
  • The executor, provisioning, or observability control plane becomes the actual product.
  • Celld’s ownership and isolation model cannot satisfy the intended tenancy.
  • Users want portable workflows rather than celld-native identities.
